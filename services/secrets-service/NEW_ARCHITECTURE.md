# Новая архитектура сервиса секретов

## Обзор

Этот документ описывает новую модульную архитектуру сервиса секретов, которая заменяет предыдущую монолитную реализацию на чистую, хорошо структурированную систему.

## Преимущества новой архитектуры

### 🔧 Модульность
- **Разделение ответственности**: Каждый модуль имеет четко определенную ответственность
- **Простота понимания**: Код легко читать и понимать
- **Легкость тестирования**: Каждый компонент можно тестировать изолированно

### 📦 Структура пакетов

```
services/secrets-service/
├── config/           # Конфигурация и настройки
├── core/             # Основная бизнес-логика
├── grpc/             # gRPC обработчики и логирование
├── http/             # HTTP админ API и middleware
├── middleware/       # HTTP промежуточное ПО
├── models/           # Структуры данных
├── storage/          # Слой работы с хранилищем (Vault)
├── utils/            # Утилиты (валидация, логирование)
├── pb/               # Protocol Buffers (генерируемые файлы)
└── main_new.go       # Новый главный файл с инициализацией
```

## Детальное описание слоев

### 1. **config/** - Конфигурация
- `config.go` - Загрузка и валидация конфигурации из переменных окружения
- Поддержка всех необходимых параметров: Vault, серверы, безопасность, rate limiting

### 2. **core/** - Бизнес-логика
- `secret_service.go` - Основной сервис секретов
- **Ответственность**: Валидация, обработка бизнес-логики, взаимодействие с хранилищем
- **Методы**:
  - `GetSecret()` - Получение общего секрета
  - `GetUserSecret()` - Получение пользовательского секрета
  - `SetUserSecret()` - Установка пользовательского секрета
  - `AdminCreateSecret()` - Создание секрета через админ API
  - `AdminDeleteSecret()` - Удаление секрета через админ API
  - `AdminListSecrets()` - Получение списка секретов

### 3. **storage/** - Слой работы с данными
- `vault.go` - Адаптер для работы с HashiCorp Vault
- **Ответственность**: Все операции с Vault (чтение, запись, удаление, список)
- **Преимущества**: Изоляция от конкретного хранилища, возможность замены на другое

### 4. **utils/** - Утилиты
- `validation.go` - Функции валидации входных данных
- `logger.go` - Структурированное логирование с zerolog
- **Ответственность**: Переиспользуемые компоненты для всего приложения

### 5. **grpc/** - gRPC API
- `handler.go` - gRPC обработчики
- `logger.go` - Специализированный логгер для gRPC
- **Ответственность**: Обработка gRPC запросов, преобразование ошибок в gRPC статусы

### 6. **http/** - HTTP админ API
- `handler.go` - HTTP обработчики для админ операций
- `logger.go` - Логгер для HTTP операций
- `models.go` - Модели данных для HTTP запросов
- **Ответственность**: REST API для управления секретами через веб-интерфейс

### 7. **models/** - Структуры данных
- `secret.go` - Общие модели для работы с секретами
- **Ответственность**: Определение структур данных, используемых во всем приложении

## Принципы проектирования

### 1. **Инверсия зависимостей**
```go
// Core зависит от абстракций, не от конкретных реализаций
type SecretService struct {
    storage   *storage.VaultStorage  // Интерфейс хранилища
    validator *utils.Validator      // Утилиты
    logger    *utils.Logger         // Логгер
    config    *config.Config        // Конфигурация
}
```

### 2. **Разделение ответственности**
- **Каждый слой** имеет четко определенную цель
- **Не смешивание** бизнес-логики с деталями реализации
- **Переиспользуемые компоненты** вынесены в utils

### 3. **Обработка ошибок**
- **Централизованная обработка** ошибок в каждом слое
- **Преобразование ошибок** в соответствующие коды (gRPC, HTTP)
- **Структурированное логирование** ошибок с контекстом

### 4. **Конфигурирование**
- **Все настройки** через переменные окружения
- **Валидация конфигурации** при запуске
- **Разумные значения по умолчанию**

## Использование

### Запуск сервиса
```bash
# Установить переменные окружения
export VAULT_ADDR="http://vault:8200"
export VAULT_TOKEN="your-vault-token"
export ADMIN_KEY="your-admin-key"

# Запустить сервис
go run main_new.go
```

### gRPC API
```go
// Пример использования через gRPC
client := pb.NewSecretServiceClient(conn)
resp, err := client.GetSecret(ctx, &pb.GetSecretRequest{
    Name: "llm/openai/api_key",
})
```

### HTTP API
```bash
# Создание секрета
curl -X POST http://localhost:8082/admin/api/secrets \
  -H "X-Admin-Key: your-admin-key" \
  -H "Content-Type: application/json" \
  -d '{"path": "llm/openai/api_key", "value": "sk-..."}'

# Получение списка секретов
curl -X GET http://localhost:8082/admin/api/secrets \
  -H "X-Admin-Key: your-admin-key"
```
